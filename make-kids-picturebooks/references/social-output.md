# 小红书与抖音社媒输出

社媒输出是印刷绘本的独立变体，不是把横向打印页截图后上传。平台 profile 必须先选定，再按该比例重新构图、生成源图和排版字幕；同一故事的角色版本、主色和道具状态可以复用，但不能复用一张已完成的画面来冒充两个 profile。

## Profile 选择

| profile | 用途 | 画布 | 源图比例 | 选择规则 |
| --- | --- | --- | --- | --- |
| `xiaohongshu-feed-3x4` | 小红书静态图文 | `1080×1440` | `3:4` | 默认 |
| `social-vertical-9x16` | 抖音/长屏 | `1080×1920` | `9:16` | 用户明确需要时显式选择 |

小红书静态图文默认3:4。一次导出只绑定一个 profile；如果同时交付两个 profile，必须分别建立 profile-specific 输出版本、源图和审核记录，不能在同一条 `social_layout` 记录里混用。不得直接缩放、中心裁切或补大块空白；比例不符时必须按目标 profile 重新构图并生成源图，不能用“人工适配决定”替代这个要求。可以沿用角色参考、主色和故事状态，但视觉焦点、主体安全区、文字安全区、平台界面避让区和图像提示词必须按 profile 分别设计。

调用渲染器时可以省略函数的 `profile` 参数；此时优先沿用页面已有的 `social_layout.profile`，因此明确记录为 `social-vertical-9x16` 的旧项目仍会沿用9:16。新页面的 `layout_design.social_layout.profile` 仍必须明确填写，项目模板默认填入小红书3:4。

## 生成前的契约

每页 `layout_design.social_layout` 至少记录 profile、画布、主体安全区、文字安全区、避让区、源图比例和状态。默认小红书示例：

```json
{
  "profile": "xiaohongshu-feed-3x4",
  "canvas": {"width_px": 1080, "height_px": 1440},
  "subject_safe_area": [0.08, 0.10, 0.84, 0.62],
  "text_safe_area": [0.08, 0.76, 0.84, 0.14],
  "avoid_regions": ["top-ui", "bottom-ui"],
  "source_aspect_ratio": "3:4",
  "status": "pending"
}
```

需要抖音/长屏时，显式改用完整的独立 profile：

```json
{
  "profile": "social-vertical-9x16",
  "canvas": {"width_px": 1080, "height_px": 1920},
  "subject_safe_area": [0.08, 0.10, 0.84, 0.62],
  "text_safe_area": [0.08, 0.76, 0.84, 0.14],
  "avoid_regions": ["top-ui", "bottom-ui"],
  "source_aspect_ratio": "9:16",
  "status": "pending"
}
```

坐标采用相对画布的 `[x, y, width, height]`，范围为 `0..1`。主体安全区应容纳人物脸、手、关键动作和知识证据；文字安全区应能放下本页字幕和对应的 `max_lines`。顶部和底部避让区是平台界面的通用保守区，不能把关键对象或字幕放进去。安全区只是设计约束，不是平台 UI 尺寸的永久保证；平台改版或投放场景变化时要重新检查。

图像生成提示词必须写明所选 profile 的比例、主体安全区、字幕安全区、关键对象不可裁切、顶部/底部避让区，以及“图像不得生成文字、伪文字或字幕”。小红书源图必须原生按3:4生成；抖音/长屏源图必须原生按9:16生成。两个 profile 都不能用直接缩放或中心裁切代替重新构图。

## 排版和导出

社媒版仍遵守“技术分层/视觉融合”：图像只负责场景，字幕由排版层加入；字幕可以在 PNG/JPEG 导出时栅格化，但应与画面自然留白、柔和文字卡或连续叙事带的颜色和动线统一。根据页面内容选择 `scene-integrated`、`soft-card` 或 `narrative-band`，不要在复杂背景上直接压默认白色矩形。

按选定 profile 逐页输出 PNG/JPEG。导出前检查 profile、画布尺寸、源图比例、字幕安全区和输出文件是否匹配；不能用一个 profile 的结果改名或简单缩放成另一个 profile。脚本通过只证明尺寸、比例、字幕几何和文件条件，不证明人物身份、场景可读性、视觉焦点或审美完成。

## 逐页审核

导出后实际查看每一页，并在 `layout_review` 或社媒审核记录中保存证据。写入 `review.json` 时，`social_pages` 每条记录必须包含独立的 `layout_review`，结构与阅读页审核相同；状态必须为 `passed`，证据必须具体描述文字、主体、遮挡、对比度和节奏，不能只写“已检查”或“通过”：

- 小红书默认画布确为 `1080×1440`、源图为3:4；抖音/长屏画布确为 `1080×1920`、源图为9:16；
- 主体和字幕没有进入所选 profile 的顶部/底部避让区；
- 人物脸、手、关键道具和知识动作完整，没有被裁掉或字幕遮挡；
- 字幕可读，行数、对比度和行距适合对应平台的阅读距离；
- 角色形象、道具状态、故事动作与相邻页一致；
- 图文属于同一场景，版式没有退化成孤立图片加默认字幕块；
- 两个 profile 若都要求交付，分别建立 profile-specific 输出版本并完成各自的逐页审核，不能相互替代或混入同一条单 profile 审核记录。

没有逐页观察和实际证据时，不能把文件存在、脚本通过或打印版已通过说成“社媒审美通过”，也不能声称自动审美通过。`layout_review` 的视觉融合、人物身份、场景可读性和故事连续性仍需人工或模型审核；技术检查不能替代这个边界。
