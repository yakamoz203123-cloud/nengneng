# 小红书与抖音竖屏输出

社媒输出是印刷绘本的独立变体，不是把横向打印页截图后上传。第一版只支持 `social-vertical-9x16`，共同基础画布为 `1080×1920`；同一故事、角色版本、主色和道具状态可以复用，但构图必须按竖屏重新安排。

## 生成前的竖屏契约

每页 `layout_design.social_layout` 至少记录：

```json
{
  "profile": "social-vertical-9x16",
  "canvas": {"width_px": 1080, "height_px": 1920},
  "subject_safe_area": [0.08, 0.10, 0.84, 0.72],
  "text_safe_area": [0.08, 0.76, 0.84, 0.14],
  "avoid_regions": ["top-ui", "bottom-ui"],
  "source_aspect_ratio": "9:16",
  "status": "pending"
}
```

坐标采用相对画布的 `[x, y, width, height]`，范围为 `0..1`。主体安全区应容纳人物脸、手、关键动作和知识证据；文字安全区应能放下本页字幕和对应的 `max_lines`。顶部和底部避让区是平台界面的通用保守区，不能把关键对象或字幕放进去。安全区只是设计约束，不是平台 UI 尺寸的永久保证；平台改版或投放场景变化时要重新检查。

图像生成提示词必须写明：`9:16 portrait composition`、主体安全区、字幕安全区、关键对象不可裁切、顶部/底部避让区，以及“图像不得生成文字、伪文字或字幕”。源图必须原生按9:16生成；比例不符就重新生成或明确记录人工适配方式，不能默认中心裁切印刷页。

## 排版和导出

社媒版仍遵守“技术分层/视觉融合”：图像只负责场景，字幕由排版层加入；字幕可以在 PNG/JPEG 导出时栅格化，但应与画面自然留白、柔和文字卡或连续叙事带的颜色和动线统一。根据页面内容选择 `scene-integrated`、`soft-card` 或 `narrative-band`，不要在复杂背景上直接压默认白色矩形。

用 `scripts/render_social.py` 逐页输出 PNG/JPEG。脚本应拒绝非 `social-vertical-9x16` profile、非9:16源图、越出文字安全区的字幕和已存在的输出文件。脚本通过只证明画布尺寸、源图比例、字幕几何和文件条件，不证明人物身份、场景可读性、视觉焦点或审美完成。

## 逐页审核

导出后实际查看每一页，并在 `layout_review` 或社媒审核记录中保存证据：

- 画布确为 `1080×1920`，主体和字幕没有进入顶部/底部避让区；
- 人物脸、手、关键道具和知识动作完整，没有被裁掉或字幕遮挡；
- 字幕可读，行数、对比度和行距适合手机竖屏；
- 角色形象、道具状态、故事动作与相邻页一致；
- 图文属于同一场景，版式没有退化成孤立图片加默认字幕块。

没有逐页观察和实际证据时，不能把文件存在、脚本通过或打印版已通过说成“社媒审美通过”，也不能声称自动审美通过。第一版暂不把 `social-note-3x4` 当成已实现 profile；需要新增比例时应先扩展契约、测试和安全区规则。
