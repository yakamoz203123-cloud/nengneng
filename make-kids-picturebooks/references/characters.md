# 固定儿童伙伴与插画

首次设定三个完全虚构的儿童伙伴，先把名字、年龄、外形、服装、颜色和标准图标为 pending（待确认），向用户展示后暂停。只有用户确认后才标为 approved（已批准）并继续正式正文、逐页插画或整册制作。偏好可以不同，知识地位平等；每个人都能观察、动手、猜错与发现。不把具体性别或角色固定成聪明、胆小或犯错的人。

## 真实儿童原型：私有角色 Bible

用户可以明确授权把自己的孩子或其他真实儿童作为绘本角色原型，但这不等于授权公开照片或个人资料。此类角色必须建立在用户自己的私有项目中，原始照片、生成的角色参考图、姓名、学校、住址、联系方式和可识别标识都不得进入 Skill 仓库、GitHub 或未经授权的外部服务。不要把真实儿童照片直接当作公开插画素材；应先由用户确认经过风格化的角色设定图，并以该设定图作为正式参考。

私有角色 Bible 至少记录以下字段：`status`（`pending`、`approved` 或 `reused`）、`version`（版本号）、`canonical_reference_path`（标准参考图路径）、`privacy_scope: private` 和 `public_release`（默认 `not-approved`）。`approved` 只表示用户批准在私有绘本项目中使用该角色，不表示照片、角色图或角色资料可以公开发布。只有用户另行明确批准公开发布时，才可把 `public_release` 改为 `approved`；发布前仍需移除原始照片、个人信息、学校／品牌标识和可追溯元数据。

每页 `character_reference_path` 必须指向当前私有项目中同一份已批准、带版本号的 character Bible 参考图；不要把用户电脑路径硬编码进 Skill 文档。角色参考应放在私有项目目录（例如项目内的 `characters/v1/`），这样清单可以用项目相对路径校验，而公开 Skill 只保存规则和空模板。若角色年龄、发型、脸部特征或核心服装设定改变，保留旧版本并建立新版本，不默默覆盖；跨年龄档使用时重新确认，不把低龄真实照片自动推断成更大年龄的角色。

提交或打包 Skill、模板和示例前，检查仓库差异与压缩包清单，确认没有儿童照片、角色参考图、私有 Bible、绝对本机路径或个人信息。若用户只批准了私有使用，任何对外发布、演示或共享都必须保持 `public_release: not-approved`，并用虚构或合成占位素材替代真实参考。

制作标准参考页：正面、侧面、身高比例、服装配色和常用表情。将这套已批准、版本化的参考页作为 character bible，保存稳定路径、批准状态与版本。项目已有 approved（已批准）角色时，可按明确版本号标为 reused（已复用）并跨书沿用，不重复索取确认；没有批准记录或无法确定版本时暂停询问。改设定时保留旧版并标记受影响册，不默默覆盖。`pending`（待确认）不等于 `approved`（已批准），样图中出现过也不会自动获得批准。

用户明确授权的临时测试角色只用于角色／画风试样，记录为 temporary（临时）并排除在正式系列角色、跨书复用清单和完成证据之外。临时角色不会因出现在样图或分镜中自动转为 approved（已批准）。

使用原创温暖手绘线条、柔和明亮色彩、丰富但不拥挤的生活场景。审美参考《波西和皮普》的阅读气质，不复制人物造型或具体构图。浅底、白边适合家用打印；不要为省墨删掉知识关键细节。

每页图像请求含：角色参考图、场景动作、构图、道具及数量、知识因果、与前页连续性、无文字要求。每页清单保存 `character_reference_path`，指向本页实际使用的 character bible 已批准版本；同一版本不得因文件名或工具默认值漂移。编辑前先查看目标图；有参考路径时依工具要求传入参考，缺少路径时按工具实际支持方式引用。不得假定参考图保证完全一致。

先完成整册分镜再生成图。插画与正文分别制作。检查实际像素和摆放尺寸：1024像素的图不能宣称在所有整页尺寸下均达300像素／英寸；可调整图像实际尺寸或按工具能力取得更清晰输出，不能伪造分辨率。

数量、桥梁连接、受力方向等需要精确时，使用程序绘制精确元素辅助呈现。程序图形不能替代故事所需儿童插画。逐页检查服装、身高、数量、动作与知识对象；失败页最多两轮针对性修订后仍有关键缺陷则保存阻碍。

图像工具缺失时保留分镜并明确仅文字完成。不要静默切换收费接口或要求用户在聊天粘贴密钥。
