# v0.5 Evaluation Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make life-model-writing evaluation runs reproducible and diagnostically useful without changing the production Skill or existing release gates.

**Architecture:** Extend the existing run manifest with optional, validated experiment metadata. Add a separate diagnostic report that consumes reviewer-provided error tags and the existing blind-test reveal mapping, so hard checks, quality scores, and error categories remain separate. Existing v0.3/v0.4 contracts remain backward-compatible.

**Tech Stack:** Python 3 standard library, JSON, unittest, existing repository scripts.

**Spec:** Current conversation v0.5 evaluation-enhancement brief; evidence and constraints in `life-model-writing/evals/v0.4.2-theory-necessity-run-1-report.md`.

## Global Constraints

- Do not modify `life-model-writing/SKILL.md` or any theory card.
- Do not rewrite or lower existing regression gates.
- Do not install external dependencies or invoke paid model APIs.
- Preserve uncommitted user files and existing baseline artifacts.
- New diagnostics must distinguish missing/unverified evidence from a pass.

## Review Focus

- A malformed experiment record must fail validation instead of silently producing a non-reproducible run; covered by metadata validation tests.
- An unknown diagnostic tag must fail closed; covered by taxonomy tests.
- A missing or non-independent diagnostic review must be unverified, not zero; covered by aggregation tests.
- A reveal mapping with missing cases must not assign errors to the wrong condition; covered by pair-mapping tests.
- Existing runs without v0.5 metadata must continue to pass current tests; covered by the full regression suite.
