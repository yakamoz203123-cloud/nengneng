# v0.3.1 回归加固与质量迭代实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不扩大架构的前提下，证明 v0.3 回归门禁可拦截坏版本，并针对盲测暴露的数字自洽、证据边界和理论—口播转换问题完成一轮可验证的 v0.3.1 改进。

**Architecture:** 保留现有 `SKILL.md → references/ → evals/` 结构。先加回归门禁的负向测试，再只修改已有规则文件；每次规则修改都重新生成同一组 v0.3 配对输出，通过独立匿名评分和 `regression_gate.py` 验收。暂不增加理论卡、模型接口或自动化服务。

**Tech Stack:** Markdown、JSON、Python 3、`unittest`、现有离线评测脚本。

**Spec:** `life-model-writing/evals/v0.3-regression.md` 与 `life-model-writing/evals/baselines/v0.3-run-1/regression-contract.json`

## Global Constraints

- 保持标准口播硬长度 800–1200 个非空白字符。
- 回归门禁必须满足 Skill 平均分 ≥28/30、单篇 ≥27/30、相对普通条件优势 ≥2分、至少3/5胜出、六维平均均 ≥4/5、关键错误为0。
- 不修改或删除 v0.3 原始基线文本、盲评评分和条件揭示。
- 不新增外部付费模型调用，不把普通模型低分直接当作门禁错误。
- 理论名称只有在改变解释时保留；理论必须落到变量、中间机制和条件性预测。
- 用户未要求视频、分镜或配音时，只交付文案 Skill 的评测和规则改进。

## Review Focus

- **数字例子内部不相容：** 数量、时间窗口和流量必须能同时成立；由 Task 2 的数字一致性案例测试。
- **无来源统计被写成社会真相：** 单个比例不能证明总体、趋势或因果；由 Task 2 的证据边界案例测试。
- **可能机制被说成必然规律：** 必须出现条件、替代解释或失效边界；由 Task 2 的事实核查测试覆盖。
- **理论名词没有增加解释：** 删除理论名称后若因果链不变，应删掉装饰性理论；由 Task 2 的理论误用测试覆盖。
- **规则改进造成口播变差：** 每次迭代同时检查理论准确性和口语自然度，不能只追求分数；由 v0.3 配对盲评保留双指标。

### Task 1: 加固 v0.3 回归门禁的负向测试

**Files:**
- Modify: `life-model-writing/tests/test_regression_gate.py`
- Test target: `life-model-writing/scripts/regression_gate.py`

**Interfaces:**
- Consumes: `evaluate_run(run_dir: Path, contract_path: Path, rubric_path: Path | None)`。
- Produces: 对长度失败、内部词泄露、Skill 单篇低于27分、无效揭示和缺失独立评分分别返回 `fail` 或 `unverified`，不能静默通过。

- [ ] **Step 1: Write the failing tests**

新增以下测试：

1. 输出包含 `内部流程` 时，结果为 `fail`，并记录 `internal-leakage`。
2. Skill 条件某篇总分为26时，结果为 `fail`，并记录 `gate-failed:min_skill_case_total`。
3. `reveal.json` 把一对中的普通稿映射到另一对时，结果为 `fail`。
4. 评分文件缺失或 `independent` 非 `true` 时，结果为 `unverified`，而不是 `pass`。

- [ ] **Step 2: Run the focused tests**

Run: `python -m unittest tests.test_regression_gate`

Expected: 新增测试在实现未改变时至少有一个失败；若现有实现已经满足某项，则保留测试作为回归保护。

- [ ] **Step 3: Make the minimal gate correction**

只修正 `regression_gate.py` 中与上述行为直接相关的逻辑，不增加新的质量指标，不改变 v0.3 阈值。

- [ ] **Step 4: Run focused and full tests**

Run: `python -m unittest tests.test_regression_gate` 和 `python -m unittest discover -s tests -p 'test_*.py'`。

Expected: focused tests与全量测试全部通过。

### Task 2: 补强证据边界与数字自洽规则

**Files:**
- Modify: `life-model-writing/SKILL.md:72-75, 111-124`
- Modify: `life-model-writing/references/fact-checking.md`
- Modify: `life-model-writing/references/theory-misuse.md`
- Modify: `life-model-writing/evals/pressure-scenarios.md`
- Test: `life-model-writing/tests/test_validate_skill.py`

**Interfaces:**
- Consumes: 现有事实三分法（已核查、待核查、模型推论）和理论误用检查。
- Produces: 在最终口播前增加一条可执行的“数字—时间窗—流量/比例自洽检查”；对无来源统计强制区分样本描述、总体判断、趋势判断和因果判断。

- [ ] **Step 1: Add failing rule-validation tests**

在 `test_validate_skill.py` 增加断言，要求规则文件能被验证器读取，并明确包含：

1. 数字、比例、时间窗口和流量关系检查。
2. 无来源统计不得推出总体、趋势或因果结论。
3. 例子内部数值不相容时必须降级、改写或删除。

- [ ] **Step 2: Run the focused validator tests**

Run: `python -m unittest tests.test_validate_skill`

Expected: 新断言先失败。

- [ ] **Step 3: Add the minimal rules**

在事实校验和理论误用规则中加入明确的四步检查：定义指标、确定分母/总体、核对时间窗、检查数字能否支持结论。规则必须要求“比例存在”与“趋势存在”分开表达，且不得用一个假设数字伪装成实证数据。

- [ ] **Step 4: Add pressure scenarios**

增加三个压力案例：

1. 仓库库存和每日销量的数字关系自相矛盾。
2. 用户提供无来源比例并要求写“整个社会越来越……”的结论。
3. 物理公式或理论类比正确，但删掉理论名称后解释不变。

- [ ] **Step 5: Run validation**

Run: `python -m unittest tests.test_validate_skill`、`python scripts/validate_skill.py .`。

Expected: 测试和结构校验通过。
