# life-model-writing 最小整改计划

制定日期：2026-10-09  
适用范围：基于 `LIFE_MODEL_WRITING_AUDIT.md` 的只读审计结论。  
本文件是建议，不代表本轮已实施；本轮没有修改 Skill 源文件、理论卡、测试或配置。

## 1. 整改目标与优先顺序

目标不是继续扩充理论数量，而是建立一条可信的质量闭环：

`规则 → 可检查中间产物 → 硬门禁 → 独立 A/B → 盲评 → 可复现回归`。

优先级：

1. 修复会直接污染所有质量结论的评分门禁。
2. 缩小理论边界，避免强行跨学科和重复理论。
3. 用固定题目证明 Skill 是否相对普通模型产生稳定增益。

## 2. 阶段一：修复评分门禁

### 要解决的问题

当前 `scripts/score_eval_run.py` 在确定性检查失败时，仍可能根据高分 JSON 汇总为 `score_status=pass`。已在临时运行中复现：结果同时为 `deterministic_status=fail` 和 `score_status=pass`。

### 修改范围

- `life-model-writing/scripts/score_eval_run.py`
- `life-model-writing/tests/` 中与评分和汇总相关的测试
- `life-model-writing/evals/verification.md`，记录新的门禁语义
- 如有必要，更新 `README.md` 中的评分说明

不修改理论卡，不借此阶段扩展 Skill 功能。

### 最小设计

保留三个相互独立的状态，避免把问题隐藏：

- `deterministic_status`：长度、空输出、版本合同、禁止的绝对断言等机器检查。
- `score_status`：人工或模型评分是否符合 rubric。
- `release_status`：最终是否允许作为通过基线；任何阻断性 deterministic failure 或关键评分失败都应阻断。

建议将检查分为：

- **阻断项**：空输出、严重短于长度合同、缺少必须字段、无法解析、严重理论误用、伪造研究结论。
- **警告项**：轻度模板重复、可选来源缺失、非关键风格偏差。

### 测试要求

至少增加以下组合测试：

1. 长度失败 + 六维高分 → `release_status=fail`。
2. 空输出 + 六维高分 → `release_status=fail`。
3. 绝对化断言触发阻断 + 高分 → `release_status=fail`。
4. 确定性通过 + 缺少评分 → `release_status=unverified`，不是 pass。
5. 确定性通过 + 低于关键维度最低线 → `release_status=fail`。
6. 确定性通过 + 合格评分 + 证据字段完整 → `release_status=pass`。

### 验收标准

- 任何阻断性确定性失败都不能进入通过计数。
- 汇总结果必须同时保留原始检查明细和最终发布状态。
- 旧版运行结果不自动重算为新标准通过。
- `python -B -m unittest discover -s life-model-writing/tests -v` 全部通过。

### 复杂度与风险

复杂度：低到中。  
主要风险：旧 baselines 依赖旧字段；应通过版本化读取和迁移说明处理，不应悄悄改写历史结果。  
回退：保留旧字段，只新增 `release_status`；若新门禁影响旧评测，标记 legacy，不删除历史数据。

## 3. 阶段二：精简和重划理论边界

### 3.1 总体原则

理论卡不按学科数量扩张，而按“是否能产生不同、可检查的条件预测”保留。每张卡至少要有：

1. 唯一的主问题范围。
2. 核心变量和方向关系。
3. 使用前提。
4. 不适用条件。
5. 一个可反事实检查的预测。
6. 一个常见误用。

### 3.2 具体文件建议

| 文件 | 建议 | 最小调整 |
|---|---|---|
| `SKILL.md` | 修改 | 把“至少两个理论”改为“一个主模型；只有在备选模型有不同预测时才比较”。要求先写变量、机制和反事实。 |
| `theory-08-networks-tipping-points-emergence.md` | 收窄或合并 | 只保留网络结构、位置和局部互动差异；将阈值扩散与传播归入 14。 |
| `theory-14-diffusion-thresholds-propagation.md` | 收窄或合并 | 只保留阈值、种子、桥接点和传播；网络结构作为输入条件而非重复理论。 |
| `theory-11-coordination-local-optima-bottlenecks.md` | 拆分概念 | 保留协调/局部最优；把瓶颈和正式队列内容移入 13 或后续窄卡。 |
| `theory-13-stocks-flows-capacity.md` | 收窄并补条件 | 明确它是存量—流量—容量语言；若加入队列子模型，写到达率、服务率、稳定条件和适用范围。 |
| `theory-10-search-stopping-matching.md` | 收窄 | 以搜索/停止为主；匹配机制若没有单独变量、算法或稳定性条件则不应挂在标题中。 |
| `theory-09-information-asymmetry-signaling-screening.md` | 补区分 | 分开发送者信号和接收者筛选，避免将两者混写。 |
| `theory-12-time-preference-attention.md` | 分层 | 区分个体的时间折扣与平台反馈/注意力容量；禁止将拖延单因归因于时间偏好。 |
| `theory-04-exponential-logistic-growth.md` | 增加边界 | 明确没有数据拟合就只能做概念模型；承载量和参数不是自动得到的现实事实。 |
| `theory-05-prisoners-dilemma-nash-equilibrium.md` | 增加形式约束 | 要求最小行动/收益说明，防止所有冲突都被命名为囚徒困境。 |

### 3.3 物理学与队列理论的范围决策

项目必须二选一，不能在描述中含糊承诺：

**方案 A：保留物理学范围。** 新增一张窄范围物理卡，处理速度、阻力、功率和单位距离能耗，必须写清车辆、路况、空气阻力、滚动阻力和效率等条件；增加“物理模型不能直接类比社会行为”的桥接规则。

**方案 B：暂不承诺物理学。** 修改 README/Skill 的范围表述，明确当前是经济学、博弈论、概率和复杂系统写作 Skill；遇到物理题目时，要求用户提供可靠模型或输出“需要物理模型核验”的降级答案。

最小迭代建议选择方案 B，除非产品确实把物理题目列为近期验收目标。队列理论先作为 13 的窄子模型验证，不应为了“学科完整”立即增加大量卡片。

### 验收标准

- 08/14、11/13、10/09、12/01 的每个概念都有唯一归属或明确关系。
- 测试 1–4 能选择主模型，且备选模型必须产生可区分预测。
- 测试 5 要么能使用有边界的物理卡，要么明确降级，不得套用社会理论。
- 删除任何一张被合并卡后，路由、链接和验证测试仍保持一致。

### 复杂度与风险

复杂度：中。  
主要风险：改卡片标题和路由会影响历史评测；历史运行应标注旧版本，不删除。  
回退：先只改路由和适用边界，不立即重写正文；确认新 A/B 有收益后再合并文件。

## 4. 阶段三：建立可复现的六题 A/B 评测

### 4.1 测试设计

固定六个输入：

1. 微信群人数越来越多，反而越来越安静。
2. 找对象时选择越多，反而越难做决定。
3. 明明知道一件事重要，却迟迟不行动。
4. 排队人数稍微增加，等待时间却可能大幅增加。
5. 汽车速度提高之后，能耗可能明显增加。
6. 用户提供无来源社会统计数据，要求写出确定性的社会结论。

每题运行两个条件：

- **A：普通模型**：不给 `life-model-writing`，只给统一的题目和最低输出要求。
- **B：Skill 模型**：加载完整 Skill，使用相同模型、参数、上下文长度和输出长度限制。

每个条件使用新鲜隔离上下文，避免 A 输出污染 B，或模型记住前一题的理论选择。

### 4.2 记录格式

每个运行必须保存：

- 输入原文和版本号。
- 模型、版本、参数、系统提示词摘要和调用时间。
- 完整原始输出，不只保存截断文本。
- 输出文件 SHA-256。
- 运行耗时、错误和人工干预。
- 确定性检查明细。
- 去条件盲评包。
- 评审者、盲化方式、评分时间和评审包哈希。

禁止把 `independent=true` 单独当作独立性证明。

### 4.3 评分

采用 100 分协议：

| 维度 | 权重 |
|---|---:|
| 理论准确性 | 20 |
| 机制推演深度 | 25 |
| 变量与反事实检验 | 15 |
| 事实可信度及边界 | 15 |
| 叙事逻辑与递进 | 10 |
| 中文口播自然度 | 10 |
| 结构完整性 | 5 |
| 合计 | 100 |

机制深度占 25 分，反事实占 15 分，防止术语和文采掩盖空洞推理。另保留阻断性错误：伪造研究、严重理论误用、无来源统计的确定性结论、群体污名化等不能用文采补偿。

### 4.4 验收标准

首轮不设置虚假的绝对分数目标，而设置证据目标：

- 六题 A/B 均有完整输出和运行记录。
- 六题均完成盲评，至少两名独立评审或一个经过记录的独立复核流程。
- 至少四题在“机制推演深度”或“事实边界”上提升；其余题目必须有可解释原因。
- Skill 条件不得增加严重理论误用或无来源确定性断言。
- 所有历史 unverified 结果继续保持 unverified，不被新结果覆盖。

若结果不满足，结论应是“Skill 尚未证明增益”，而不是继续调参直到通过。

## 5. 阶段四：补齐自动化测试矩阵

### 必测类别

1. **评分门禁**：见阶段一六类组合。
2. **输入错误**：空题目、超长题目、混合中英文、只有统计结论无来源。
3. **理论缺失**：没有合适卡片时必须降级，不得随机套卡。
4. **理论冲突**：两个模型预测方向不同，必须分别写条件，不能强行合并。
5. **单理论题**：模型能判断只需一个主理论，不因没有第二理论而失败。
6. **物理误用**：社会问题不能直接使用物理定律，物理题不能用网络/博弈论冒充物理解释。
7. **事实状态**：外部事实、模型推论、经验判断、未知必须可识别。
8. **长度**：短、标准、长三个合同，输出不足不能被高分绕过。
9. **跨平台路径**：Windows 反斜杠与 POSIX 斜杠互读。
10. **盲评包完整性**：缺输出、缺哈希、泄漏条件或被替换时必须失败。
11. **版本兼容**：v0.1 历史案例与 v0.2 当前案例不能混为同一基线。
12. **内容回归**：六题固定输入至少做结构性检查，不把文件存在当作能力通过。

### 验收标准

测试报告必须输出命令、通过、失败、跳过、阻塞原因和运行环境；每个失败都要有最小复现输入，而不是只显示“assertion failed”。

## 6. 阶段五：口播质量整改

### 要修改的规则

在 `references/structure-patterns.md` 和 `references/spoken-script-style.md` 中增加以下硬要求：

- 每个核心段落必须推进一个新变量、机制或条件，不得只换说法。
- 至少出现一次“如果关键变量改变，预测如何变化”的具体反事实。
- 理论名称首次出现时解释其与当前变量的关系，不连续堆名词。
- 结尾回到真实生活，但必须区分模型推论与建议。
- 800–1200 字是 standard 合同，历史短文本只能标 legacy，不得静默通过。

在 `theory-misuse.md` 中增加：

- 纳什均衡不是必然发生的现实结果。
- 物理公式的社会类比必须说明同构关系和失效条件。
- 相关性、机制解释和因果识别要分层。
- “研究表明”“数据显示”必须有来源或改写为“在这个模型里”。

### 验收标准

盲评者能指出文案中的：结果变量、主机制、至少一个反事实和至少一个边界；若不能指出，即使文本流畅也不得评为高机制分。

## 7. 分阶段执行顺序

### Phase 1：可信门禁

- 范围：评分脚本、单测、验证说明。
- 先决条件：确定阻断项和警告项。
- 通过标准：不再出现 deterministic fail / release pass。
- 复杂度：低到中。

### Phase 2：范围和理论整理

- 范围：`SKILL.md`、重叠卡片、路由和理论测试。
- 先决条件：Phase 1 已能可靠判断回归。
- 通过标准：每个主题有唯一主模型，只有真竞争才引入备选模型；物理范围明确。
- 复杂度：中。

### Phase 3：A/B 证据

- 范围：六题、两条件、完整记录、盲评。
- 先决条件：模型调用权限和费用批准；固定评分协议。
- 通过标准：完整、可复核、无伪造；是否有增益由结果决定。
- 复杂度：中。

### Phase 4：公开测试发布

- 范围：README、版本号、canonical eval 集、CI 真实运行记录。
- 先决条件：Phase 1–3 至少完成并暴露剩余失败。
- 通过标准：公开文档不夸大能力；所有未验证项显式标记；新用户能在干净环境复现结构验证和评测脚本。
- 复杂度：低到中。

## 8. 不建议现在做的事情

- 不要一次新增大量经济学、数学或物理理论卡。
- 不要用更长的提示词掩盖缺少反事实和独立评测的问题。
- 不要把历史 GREEN 记录重命名为当前通过证据。
- 不要把 29/29 工程测试通过解释为文案质量通过。
- 不要把“输出听起来有理论”作为跨学科能力的验收标准。
- 不要为了达到 800–1200 字而填充重复解释；长度门禁与内容推进必须分开评估。

## 9. 最小版本迭代方案

如果只能进行一次迭代，采用以下范围：

1. 修复 `score_eval_run.py` 的最终发布状态合并逻辑。
2. 增加失败组合测试和一个可复现的短输出回归。
3. 将 `SKILL.md` 的“至少比较两个理论”改为“主模型+必要时的真竞争备选模型”。
4. 暂不新增理论卡；在 README 中明确当前没有正式物理学卡和完整队列理论。
5. 使用现有六个输入，在同一模型上完成普通/Skill A/B；如果没有授权调用，则明确记录为阻塞，不填补虚构结果。
6. 只输出一份带原始文案、评分明细和失败原因的试验报告，不用总分掩盖单题问题。

这次迭代的核心验收不是“平均分变高”，而是：坏输出不能再被错误判为通过，并且能回答 Skill 到底是否带来可复现增益。

## 10. 回退与风险控制

- 所有修改前保留当前 Git 提交和历史评测；不重写旧 baseline。
- 理论合并采用“先改路由、后合并文件”的顺序，避免一次性破坏引用。
- 新评分字段向后兼容旧结果；旧结果标记为 legacy/unverified。
- A/B 试验不进行未经授权的付费调用；没有授权时只完成测试夹具和静态检查。
- 不在整改过程中删除理论卡；确认新卡边界和路由稳定后再讨论归档。
- 任何内容质量结论都必须引用原始输出、评分者和运行配置。

## 11. 预期结果

整改完成后，项目应能明确区分四种状态：

1. 工具和目录结构正确。
2. 输出满足机器合同。
3. 输出通过理论/事实/边界质量审核。
4. Skill 相对普通模型是否产生增益。

这四种状态不能再用一个“测试通过”或一个总分混在一起。只有在 P0 门禁修复、六题 A/B 可复核、理论范围明确且不存在严重误用后，项目才有资格从“公开测试版本”讨论是否进入“工程可用”或“稳定版本”。
