# v0.3 基线盲测与回归流程

这套流程把本次 5 个主题、10 篇匿名文案固定为 `v0.3-run-1`。以后修改 Skill 的规则、理论卡或评测脚本后，必须用同一组题目、同一组 X/Y 匿名协议和独立评分重新跑一次；不能只看一篇示例，也不能把计划或人工印象当成通过证据。

## 基线位置

- 题目：`evals/v0.3-blind-cases.json`
- 回归契约：`evals/baselines/v0.3-run-1/regression-contract.json`
- 基线文本：`evals/baselines/v0.3-run-1/outputs/`
- 条件揭示：`evals/baselines/v0.3-run-1/reveal.json`
- 匿名盲评：`evals/baselines/v0.3-run-1/blind-review.md`
- 结构化评分：`evals/baselines/v0.3-run-1/scores/`

`reveal.json` 只能在盲评完成后使用。提交给盲评者的材料只能包含题目、X/Y 标签、文案和评分标准，不能包含 Skill/普通模型对应关系。

## 每次迭代的标准步骤

### 1. 固定输入和生成条件

使用相同的题目文件和可比的模型配置，在新鲜上下文中生成 10 篇输出。每个主题生成 X、Y 两篇，文件名只使用 `t01-x.md`、`t01-y.md` 这类匿名标签。生成时记录模型、版本、参数、调用方式和是否发生人工干预。

### 2. 建立运行目录

```powershell
python scripts/create_eval_run.py `
  --skill-root . `
  --cases evals/v0.3-blind-cases.json `
  --run-id v0.3-run-2 `
  --model-name GPT-5 `
  --invocation-mode paired-anonymous-manual-generation `
  --human-intervention "none during generation"
```

将生成的匿名输出导入新运行目录：

```powershell
python scripts/import_outputs.py `
  --run-dir evals/runs/v0.3-run-2 `
  --source-dir path/to/anonymous-outputs
```

### 3. 独立匿名盲评

盲评者只读取 `outputs/`，对每一对 X/Y 按 `evals/rubric.json` 的六个维度评分，并把每个评分保存为 `scores/<case-id>.json`。评分文件必须写明 `evaluator.independent: true`，但不得透露条件来源。评分前不得读取 `reveal.json`。

### 4. 盲评完成后揭示条件

把本轮真实条件写入运行目录的 `reveal.json`，格式与基线一致：每一对必须明确 `skill_case_id` 和 `ordinary_case_id`，但两者只能来自该对的 X/Y 文件。

### 5. 执行唯一回归门禁

```powershell
python scripts/regression_gate.py `
  --run-dir evals/runs/v0.3-run-2 `
  --contract evals/baselines/v0.3-run-1/regression-contract.json `
  --write-checks `
  --write-report
```

退出码为 `0` 才算通过。报告写入运行目录的 `regression-summary.json`，应随运行结果一同保留。

## 必须通过的门槛

### 不依赖主观评分的硬检查

- 恰好 10 个预期输出，不能缺失或多出。
- 每篇去除空白后 800–1200 字。
- 不出现 `Skill`、`理论卡`、`内部流程`、`问题建模`、`候选理论`、`检查表`、`评测` 等内部泄露词。
- 所有输出均为 UTF-8 且非空。

### 相对质量门槛

- Skill 条件平均分不低于 28/30。
- Skill 条件每篇不低于 27/30。
- Skill 相对普通条件的平均优势不低于 2 分。
- 5 对中 Skill 至少赢 3 对；平局不算赢。
- Skill 六个维度的平均分都不低于 4/5。
- 关键错误数量为 0；关键错误包括严重理论误用、虚构研究、无支持因果和群体污名化。

低分普通稿本身不是回归脚本错误；它是对照组的观测结果。只有 Skill 条件跌破门槛、配对优势消失、评分缺失/不独立，或硬检查失败，才阻断迭代。

## 解释失败时怎么处理

回归失败后先保留运行目录和报告，不立即修改基线阈值。按照报告定位是长度/泄露、输入调用、理论推理、事实边界还是口播表达下降；修复后用新的运行编号重跑。只有当题目、评分标准或产品目标发生有记录的变化时，才允许建立 `v0.4` 新基线，并在变更说明中解释为什么不能继续与 v0.3 直接比较。
