# v0.5 三轮盲测包

这是一组独立于现有 v0.3/v0.4 基线的泛化测试。它不修改生产 Skill，也不把尚未调用模型生成的结果计入成绩。

## 一、固定实验条件

每个题目做 3 轮，每轮都生成两个版本：

- `ordinary`：不加载 `life-model-writing`；
- `skill`：加载当前 `life-model-writing`；
- 两组必须使用同一个模型、后端、系统设置、温度、随机种子和输入题目；
- 只改变是否加载 Skill；
- 输出长度统一为 800—1200 字中文口播；
- 生成后不得人工润色再进入盲评；
- 如果没有真实模型输出、模型配置或独立评审，标记为 `unverified`，不计 0 分。

推荐记录的实验元数据：

```json
{
  "engine": "<实际调用引擎>",
  "condition": "ordinary 或 skill",
  "repeat_index": 0,
  "sampling": {
    "temperature": 0.2,
    "seed": null
  }
}
```

`repeat_index` 使用 `0`、`1`、`2`。三轮不能用同一个已经生成过的输出冒充重复实验。

## 二、两组固定提示词

### A. ordinary 组

```text
你是一名中文长口播文案作者。

请围绕下面的生活问题，写一版800—1200字、可以直接朗读的中文口播文案。

要求：
1. 从具体生活场景开头；
2. 解释现象形成的原因；
3. 语言自然，不写成论文；
4. 不编造研究、数据、机构或来源；
5. 如果结论有条件，请说明边界和例外；
6. 只输出最终口播文案，不展示分析过程，不列提纲。

生活问题：
<把测试题目粘贴在这里>
```

### B. skill 组

```text
请调用并严格使用 life-model-writing Skill，围绕下面的生活问题，写一版800—1200字、可以直接朗读的中文口播文案。

必须在内部完成，不要把内部分析过程展示给用户：
1. 先定义问题中的关键概念和可观察结果；
2. 至少比较两个真正不同的候选理论，判断主模型和补充模型；如果第二个理论不能改变预测，就不要硬加；
3. 明确2—4个关键变量，以及变量之间的方向、阈值或简化公式关系；
4. 推演“为什么会发生”，不要只罗列理论名词；
5. 做至少一个反事实检查：改变关键条件后，结论是否会反转；
6. 区分已知事实、模型推论和未知信息；没有来源的数字不得写成事实；
7. 检查理论误用、错误因果、过度概括和不恰当类比；
8. 最终只保留自然口语、具体场景、逐层递进和克制收束，不暴露 Skill、理论卡或内部流程。

只输出最终口播文案，不输出模型卡、评分、提纲或解释过程。

生活问题：
<把测试题目粘贴在这里>
```

## 三、五个全新测试题

### v05-fresh-01：为什么会议参加的人越多，决定反而越慢？

重点观察：是否能区分协调成本、信息聚合和责任分散；是否能说明人数增加并非必然导致低效，以及明确决策权、异步提供信息后结论如何变化。

### v05-fresh-02：为什么便宜的长期订阅，反而更容易被人忘记取消？

重点观察：是否能区分沉没成本、默认选项、注意力成本和即时支付痛感；不能把“用户懒”当成完整因果解释，也不能把所有订阅行为都归因于平台操纵。

### v05-fresh-03：为什么同样长度的队伍，移动得快时感觉没有那么难等？

重点观察：是否能区分客观等待时间、等待过程中的信息反馈和主观时间感受；不得把心理感受直接写成排队系统吞吐量发生变化。

### v05-fresh-04：为什么下雨天打车更难，价格也可能更高？

重点观察：是否能联合供需、动态定价和风险/时间成本解释现象；必须保留“可能”与适用条件，不能把所有涨价都说成平台单方面操纵，也不能忽略司机供给变化。

### v05-fresh-05：为什么手机电量还剩很多，有些人却开始焦虑？

重点观察：是否能区分实际剩余电量、未来不确定性、损失规避和安全缓冲；不能把一个心理倾向扩大成所有人的普遍规律，也不能伪造心理学统计。

## 四、文件命名和盲测顺序

每个题目每轮保存两个原始输出：

```text
v05-fresh-01-r0-ordinary.md
v05-fresh-01-r0-skill.md
v05-fresh-01-r1-ordinary.md
v05-fresh-01-r1-skill.md
v05-fresh-01-r2-ordinary.md
v05-fresh-01-r2-skill.md
```

盲评前将条件隐藏，改成随机编号，例如 `sample-001.md`。盲评完成并保存独立评分后，才写入 `reveal.json`，不能提前向评审者暴露 ordinary/skill 标签。

## 五、盲评记录

每个样本使用现有 `rubric.json` 的六个维度评分，并额外填写错误标签：

- `fabricated_research`
- `quantitative_error`
- `severe_theory_misuse`
- `unsupported_causality`
- `theory_decoration`
- `missing_counterfactual`
- `missing_boundary`
- `evidence_overclaim`
- `oral_stiffness`
- `length_or_structure`

关键错误必须单独统计，不允许被平均分掩盖。没有独立评审的样本，诊断状态保持 `unverified`。

## 六、v0.5 通过条件

三轮完成后，分别计算 ordinary 与 skill 的：

1. 六维平均分和每轮方差；
2. 理论装饰、因果越界、公式错误、证据过度断言等错误率；
3. 严重错误数量；
4. 缺失输出、缺失评分和非独立评审数量；
5. 每个题目在三轮中的胜负变化。

只有同时满足以下条件，才能把结果作为 v0.5 候选证据：

- 三轮的模型、后端、参数和输入可核验；
- 两组都完成相同题目，且盲评映射完整；
- Skill 组没有新增严重理论或事实错误；
- Skill 组的关键错误率不高于 ordinary 组；
- Skill 组不是只靠增加术语获得分数，而是在机制、边界和反事实上有可核验证据；
- 所有缺失证据都被单独标为 `unverified`，没有用 0 分填补。

如果只提升总分、但理论装饰或口播僵硬错误率上升，不通过 v0.5。
