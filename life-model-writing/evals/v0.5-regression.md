# v0.5 回归评测流程

v0.5 不修改文案生成规则，也不替换 v0.3 正式回归基线。它增加两项证据：可复现的实验元数据，以及独立评审错误分类。

## 1. 运行原则

同一配对测试必须满足：

- X 与 Y 使用同一个模型、后端、参数和输入；
- X 不加载 `life-model-writing`，Y 加载当前 Skill；
- 每个配对至少重复 3 次，`repeat_index` 从 0 开始；
- 每次运行保存 Skill commit、模型配置、采样参数、提示哈希和人工干预说明；
- 不使用付费模型调用时，不得把缺少输出标成 0 分，必须标为 `unverified`。

## 2. 实验元数据

严格运行通过 `scripts.create_eval_run.create_run(..., experiment=...)` 写入以下字段：

```json
{
  "engine": "codex",
  "condition": "paired-ab",
  "repeat_index": 0,
  "sampling": {
    "temperature": 0.2,
    "seed": null
  }
}
```

`eval_common.validate_experiment_metadata` 会拒绝缺字段、负重复编号、非法温度和非法种子。现有命令行入口仍用于旧版手动导入；在没有真实 provider runner 之前，不把它伪装成完整的严格 A/B 运行器。

当前仓库已经提供 DeepSeek Runner：`scripts/run_deepseek_eval.py`。它使用标准库调用 DeepSeek 的 OpenAI 兼容 Chat Completions 接口，不需要把 API Key 写入文件。Skill 组只加载 `SKILL.md` 和 `evals/v0.5-reference-routes.json` 为当前题目声明的参考资料，不再默认发送全部理论库。

Windows PowerShell 中先在同一个运行环境设置密钥：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host "DeepSeek API Key"
```

先做不调用模型的检查：

```text
python scripts/run_deepseek_eval.py --skill-root . --cases evals/v0.5-test-cases.json --routes evals/v0.5-reference-routes.json --run-id v0.5-dry-run-r0 --repeat-index 0 --pair-id v05-fresh-01 --dry-run
```

确认环境和额度后，先只跑一个配对：

```text
python scripts/run_deepseek_eval.py --skill-root . --cases evals/v0.5-test-cases.json --routes evals/v0.5-reference-routes.json --run-id v0.5-deepseek-r0 --repeat-index 0 --pair-id v05-fresh-01 --model deepseek-flash --temperature 0.7 --thinking disabled --allow-paid
```

完整一轮不传 `--pair-id`，会生成 5 个题目的 10 个输出；三轮使用不同的 `--run-id` 和 `--repeat-index 0/1/2`，合计 30 次调用。Runner 会写入 `outputs/`、`provider-records/`、`manifest.json` 和 `reveal.json`。这些 run 目录默认被 `.gitignore` 忽略，评测报告只引用其摘要和哈希。

## 3. 错误分类

独立评审在 `diagnostics/<case-id>.json` 写入：

```json
{
  "case_id": "v05-01-x",
  "evaluator": {
    "type": "human",
    "name": "reviewer",
    "independent": true
  },
  "error_tags": ["missing_counterfactual"]
}
```

允许的标签见 `error-taxonomy.json`。其中以下标签会阻塞诊断通过：

- `fabricated_research`
- `quantitative_error`
- `severe_theory_misuse`
- `unsupported_causality`

运行诊断：

```text
python scripts/diagnose_eval_run.py \
  --run-dir evals/runs/<run-id> \
  --taxonomy evals/error-taxonomy.json
```

输出状态含义：

- `pass`：所有案例都有独立诊断，且没有阻塞错误；
- `fail`：存在非法记录、错误标签或阻塞错误；
- `unverified`：缺少输出、缺少诊断或评审没有声明独立性。

结果写入 `<run-dir>/diagnostics-summary.json`，并分别统计 `skill` 和 `ordinary` 条件的错误案例率与标签数量。

Runner 生成输出后，必须先完成独立盲评，再运行上面的诊断脚本。没有 `diagnostics/<case-id>.json` 或评审未声明 `independent: true` 时，结果只能是 `unverified`，不能当作 Skill 通过或失败。

## 4. 解释结果

总分仍由 `score_eval_run.py` 和既有回归合同负责。诊断报告不自动改变 v0.3 门禁，只回答另一个问题：Skill 是否减少了普通模型容易犯的特定错误。

每轮报告至少记录：

1. Skill 与普通组的平均分、方差和胜平负；
2. 每个错误标签的案例率；
3. 严重错误数量；
4. 缺失或未验证案例数量；
5. 模型、配置、Skill commit 和重复编号。

只有在同模型、同配置、至少三次重复，并且 Skill 组关键错误率没有高于普通组时，才把结果作为 v0.5 候选发布证据。
